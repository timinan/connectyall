Connectyall Design System

A reference for everything visual in the app. Update this when you change the system; check this before you add new UI.

Maintained alongside the codebase at docs/design-system.html. Open in a browser to view.

Core principles

Five rules that govern the whole product. If a change breaks one of these, it's the wrong change.

  1. Voice in, connection out. Every screen exists in service of the voice → connection pipeline. Decoration that distracts from that loses.
  2. Warm content, engineered chrome. Conversational text (names, notes, recaps) reads in Sora — warm and human. Labels, tags, dates, buttons read in JetBrains Mono uppercase — engineered and precise. Two voices, distinct slots.
  3. Every page is aligned to every other. Logo, status pill, and headline banner sit at the same x/y on every page. Tab through marketing → sign-in → profile → record → connections to verify before shipping.
  4. Tap-to-edit, not always-editing. Profile + connection detail show values as text + pencil. Tap a value → it becomes an input with check + X. No persistent form fields.
  5. Brand purple is the single accent. One brand color (#7C5CFF) used everywhere a thing is interactive, important, or branded. Black is structural. Red is for destructive only.

Brand voice

Connectyall is "the voice note that turns into a connection." The brand is warm, casual, and conversational — never enterprise, never cold. We use first person ("we"), contractions, and short sentences.

Tagline

Voice notes that connects y'all. Talk it out. We pull the name, the channels, the gist. Built in an instant. Shared in a tap.

Tonal rules

  • Lead positive. "Tap to record" not "Don't waste time typing."
  • Conversational. "Hang tight while we turn your voice into a connection." Not "Processing audio for entity extraction."
  • No corporate jargon. Never: leverage, utilize, robust, streamline, cutting-edge, harness, unlock.
  • No em-dashes in product copy. Use periods or "—" only sparingly.
  • Mono labels are ALL CAPS with leading ●. Examples: ● GOOD EVENING, TIM · ● MET TODAY · 2 MEETINGS · ● NO PASSWORD NEEDED

Spacing & layout

We use Tailwind's default 4px-based scale. The most important numbers to know by heart:

  • px-4 (16px) → horizontal padding on mobile
  • sm:px-6 (24px) → horizontal padding on tablet+
  • sm:max-w-xl (576px) → max width of logged-in pages
  • pb-28 (112px) → bottom padding on app pages to clear the floating nav
  • pl-5 (20px) → indent for body text + mono labels so they line up with where the headline text starts inside the banner card (4px border + 16px padding = 20px)
  • gap-4 (16px) → vertical rhythm between cards
  • gap-1.5 (6px) → tight horizontal gaps inside compound buttons (icon + label)

Border radius

  • rounded-full → pills, circles, CTAs (every action surface)
  • rounded-r-2xl (16px right corners) → headline-banner cards (purple left edge stays flat)
  • rounded-3xl (24px) → modal containers, sign-in input boxes
  • rounded-2xl (16px) → content cards (profile, connection detail)
  • rounded-lg (8px) → cream value-input boxes

Shadows

Three tiers. Each is purpose-bound — don't invent new ones.

Card lift · subtle

shadow-[0_2px_8px_rgba(0,0,0,0.04)]

Headline banners, content cards, navigation pills. Quiet — the card looks like it sits on the page.

Floating · row card

shadow-[0_8px_24px_rgba(0,0,0,0.06),0_2px_4px_rgba(0,0,0,0.04)]

Connection list rows — the "tap me, I'm pressable" weight without competing with the headline.

Brand glow · primary CTA

shadow-[0_16px_36px_rgba(124,92,255,0.42),0_2px_6px_rgba(124,92,255,0.20)]

Every brand-purple primary CTA. Communicates "this is THE action." Do not use on secondary buttons.

Container constants

Every page MUST use one of three exported constants from src/app/app/_layout-constants.ts. Never hand-roll px-* or max-w-* on the outer page wrapper.

// Logged-in stacking pages (profile, connections list)
APP_CONTAINER       = 'px-4 py-6 pb-28 sm:px-6 sm:max-w-xl sm:mx-auto space-y-4 w-full';

// Logged-in vertical-flex pages (record / processing — mic centers in dvh)
APP_CONTAINER_FLEX  = 'px-4 py-6 pb-28 sm:px-6 sm:max-w-xl sm:mx-auto w-full min-h-[100dvh] flex flex-col';

// Public / auth pages (marketing root, sign-in) — no bottom-nav clearance
LANDING_CONTAINER_FLEX = 'px-4 py-6 pb-8 sm:px-6 sm:max-w-xl sm:mx-auto w-full min-h-[100dvh] flex flex-col';

Picking the wrong container drifts the logo + status pill 8px between tabs. Tim flagged this twice during the UI refresh; the fix both times was to stop hand-rolling padding and use the shared constant.

Alignment rules

Two rules. Verify both by tabbing through every page.

Do

Mono label always sits below the headline banner. Format: ● UPPERCASE TEXT

Text under the banner gets pl-5 (20px) so it lines up with where the headline letters start inside the banner card. The banner has a 4px purple border + px-4 (16px) padding = 20px text-start indent.

Don't

Don't put the mono label above the banner. That was sign-in's pattern until 2026-06-18 and it broke the rhythm with every other page.

Don't let the mono label or body text start at the container's left edge. That visual offset is what made Tim flag every page during alignment passes.

Tap-to-edit pattern

Profile + connection detail share this pattern. Every value renders as plain text + a pencil icon. Tap → input appears with check + X buttons that replace the pencil.

Three implementations

  • EditableLine (profile-editor.tsx) — single-line input. Used for NAME / TITLE on profile.
  • EditableTextArea (connections/[id]/page.tsx) — textarea that starts at rows={1} and auto-grows via scrollHeight. Used for PRIVATE NOTE / WHAT WE TALKED ABOUT.
  • EditableField (connections/[id]/page.tsx) — channel value with star (preferred) + send/visit pill + delete X on the right. Used for every channel row.

Critical pattern: onMouseDown.preventDefault() on check + X

Why this exists: Without it, tapping the check button caused the input to blur first (mobile keyboard collapses, layout shifts), and the click could register on the wrong element. Symptom: check button "reverted" the change. Fix is two-part:
  1. Add onMouseDown={(e) => e.preventDefault()} to every check + X button so focus stays put.
  2. Capture const next = draft synchronously before setEditing(false) in commit().
Applied to all three editable components. Don't remove either piece.

Glow rings

Three concentric radial circles centered on the page's focal element (mic, avatar, sign-in form). Brand-purple by default; red on the recording state.

Animation: glow-breathe

@keyframes glow-breathe {
  0%, 100% { transform: scale(1);    opacity: 0.78; }
  50%      { transform: scale(1.14); opacity: 1; }
}
.glow-breathe       { animation: glow-breathe 4.5s ease-in-out infinite; }
.glow-breathe-d1    { animation-delay: -1.5s; } /* inner ring 1 */
.glow-breathe-d2    { animation-delay: -3s;   } /* inner ring 2 */

Apply .glow-breathe to the outer ring, -d1 / -d2 to the inner two. The negative delays put each ring at a different phase so the rings ripple outward in a layered wave instead of pulsing in sync.

Sizing rules

  • Outer ring: 300–360px typically. Sign-in's GlowRings is 480px (more presence for the form).
  • Inner inset 1: ~30–60px inside the outer. Inner inset 2: ~60–120px inside.
  • Don't let the breathing peak overlap text. Peak size = base × 1.14. If you have body text above the glow, leave at least (base × 1.14 - base) / 2 of vertical clearance.
  • The profile avatar glow is centered on the photo, not the surrounding block. Wrap the avatar in its own relative div and put the glow inside with top-1/2 -translate-y-1/2.

Tuning rules

  • Logo spinner timing is calibrated. 4 bounce-pauses per full rotation at 2.4s. If you change the duration, you must rescale the keyframe percentages proportionally — the bounce overshoot/recoil/settle pattern only works at the original ratio.
  • Glow breathe delays are absolute, not relative. -1.5s and -3s are picked to land each ring at a distinct phase of a 4.5s cycle. Changing the duration without rescaling delays breaks the wave.

Page transitions

We use the browser-native View Transitions API to mask server-render latency. Two wrappers exist:

BottomNav

Wraps router.push() in document.startViewTransition() and adds vt-slide-left or vt-slide-right to <html> based on whether the new tab is to the left or right of the current one in TABS. Pages slide; the nav itself is pinned via view-transition-name: bnav so it stays put.

ViewTransitionLink

Drop-in replacement for next/link. Used for marketing → sign-in to mask the blank-white flash between server-rendered pages. Falls back to normal navigation on Firefox.

// src/components/view-transition-link.tsx
import { ViewTransitionLink } from '@/components/view-transition-link';

<ViewTransitionLink href="/app" className="...">
  Open the app
</ViewTransitionLink>

When to use which

  • Use the bottom-nav itself for in-app tab switches. It handles direction.
  • Use ViewTransitionLink for any cross-page link outside the bottom-nav (marketing CTA, sign-in, public landing).
  • Don't use either for in-page actions (modals, tap-to-edit). Those are React state changes, not navigations.

Anti-patterns

Things we've explicitly decided against. Each is here because someone tried it and Tim said no.

Don't hand-roll px-* on the outer page wrapper

Use APP_CONTAINER / APP_CONTAINER_FLEX / LANDING_CONTAINER_FLEX. Each page that deviated by 8px broke alignment across tabs.

Don't put the mono label above the banner

Always below. Sign-in's old layout was the only outlier; we fixed it.

Don't use icons on send/visit/add buttons

Text only. SEND, VISIT, ADD. The mono caps carry the meaning. The paper-plane icon was removed app-wide.

Don't use emoji in chip labels

The 💾 in "Save X to phone" was removed. The ✓ checkmark on "Save" was removed. Use mono uppercase text on its own.

Don't add multiple channels of the same kind

One email, one phone, one of each social. The Add-field dropdown filters them out once present.

Don't use color icons in channel rows

All channel icons render in currentColor (black). LinkedIn blue, X red, etc. were removed for consistency.

Don't add corporate jargon

Never: leverage, utilize, robust, streamline, cutting-edge, harness, unlock. Use plain English.

Don't bold the value text in profile fields

Use the default body weight. The original font-bold tracking-tight on NAME / TITLE was a legacy rule; removed for parity with connection-detail's plain values.
